01

The Challenge

I wanted scroll-triggered reveal animations, elements fading and lifting into place as you scroll down, without pulling in a single animation library. That was a rule I set for this project: zero dependencies, which meant no GSAP, no ScrollTrigger, nothing installed.

The naive way to detect "has this element scrolled into view" is a scroll event listener that checks every tracked element's position on every scroll tick. That runs dozens of times a second, on every pixel of scroll, checking geometry for every section on the page. It works, but it's exactly the kind of janky, battery-draining pattern that undermines a project whose whole pitch is performance thinking.

There was a second requirement hiding inside the first one: some visitors set their operating system to reduce motion because animation causes them discomfort or distraction. A portfolio that ignores that setting isn't accessible, no matter how smooth the animation looks to everyone else.

02

How I Fixed It

I replaced the scroll listener with the IntersectionObserver API, which lets the browser tell me when an element enters the viewport instead of me polling for it. Each revealable section gets tagged once on load, one observer watches all of them, and the moment an element crosses the visibility threshold, it gets a "visible" class and the observer stops watching that element, since it only needs to reveal once.

For motion sensitivity, the reveal transition lives inside a prefers-reduced-motion media query. If a visitor has that setting on, the transition is removed entirely and every element appears instantly in its final position. No missing content, no waiting on an animation that never runs the way they expect.

script.js 
const revealObserver = new IntersectionObserver(
  (entries) => {
    entries.forEach(entry => {
      if (entry.isIntersecting) {
        entry.target.classList.add('visible');
        // stop watching once it has revealed
        revealObserver.unobserve(entry.target);
      }
    });
  },
  { threshold: 0.12 }
);
03

What Changed

  • Scroll reveal costs one observer, not a scroll listener firing dozens of times a second
  • Each element stops being watched once it has revealed, keeping the observer lightweight as the page grows
  • Motion-sensitive visitors get the same content instantly, with no animation forced on them

The lesson: a smooth animation and a fast, accessible page aren't a trade-off once you pick the right browser API. You just have to know it exists before reaching for a library.
