Academic Publications Platform

A research and publications platform built for Prof. Aondona Paul Ihom, bringing 200+ journal publications, authored books, and ongoing research under one roof, with a monetization option and an admin dashboard that cut manual upkeep to almost nothing.

01

The Challenge

The professor's publication list runs past 200 entries and keeps growing every time a new paper is indexed on Google Scholar. Re-typing that list by hand every time a paper comes out was exactly the manual overhead this project was meant to remove.

The obvious fix, pulling the list straight from Google Scholar, runs into a hard limit: Google Scholar has no official public API. Any automated way of reading it means scraping a page built for humans, not scripts, and Google actively rate-limits and blocks requests that look automated. Build that naively, on every page load, and the public site either shows a stale, half-loaded list or breaks outright the moment Google throttles the request.

That is not acceptable on a site tied to someone's academic reputation. It needed to look current at all times, not only when the scrape happened to succeed.

02

How I Fixed It

I stopped treating Google Scholar as a live data source and started treating it as a periodic import. A scheduled sync job pulls the publication list on its own schedule, independent of any visitor's request, and writes the results into the platform's own database. Visitors always read from that database, never from Google directly, so a blocked or slow scrape never becomes a visitor-facing error.

I paired that with a fallback in the admin dashboard: if a sync fails, or a new paper needs to show up before the next scheduled run, the professor can add or edit a publication entry by hand. The public page never depends on the scrape succeeding in order to look complete.

syncPublications.js 
async function syncPublications() {
  try {
    const results = await scholarScraper.fetchLatest(profileId);
    await Publication.bulkUpsert(results);
  } catch (err) {
    logger.warn('Scholar sync failed, keeping last known list', err);
  }
}
// Runs on a schedule, never on the request path
cron.schedule('0 3 * * *', syncPublications);
03

What Changed

  • The publication list stays current without daily manual re-entry from the professor
  • A blocked or failed sync never shows up as a broken page to visitors
  • The professor can override or add entries directly through the admin dashboard whenever needed

The lesson here: when a third-party source can't be trusted to answer instantly and reliably, don't put it on the request path. Sync it in the background and let your own database be the source of truth.
